# เอกสารตัวอย่างสำหรับทดสอบ

**ข้อมูลทั้งหมดเป็นข้อมูลสมมติ** (หน่วยงาน เลขที่หนังสือ ชื่อบุคคล ที่อยู่ เบอร์โทร) ไม่ใช่เอกสารราชการจริง ใช้ทดสอบ extension และวัดความแม่นยำเท่านั้น

| ไฟล์ | ประเภท | สิ่งที่ทดสอบ |
|---|---|---|
| `s1-external-clean.pdf` | หนังสือภายนอก | พิมพ์ชัด เลขไทย เดือนเต็ม อ้างถึง/สิ่งที่ส่งมาด้วยหลายข้อ ตราประทับ "ด่วนมาก" |
| `s2-internal-memo.pdf` | บันทึกข้อความ | ส่วนราชการ+เบอร์โทรในบรรทัดเดียว วันที่แบบย่อ (`๕ ส.ค. ๒๕๖๙`) ไม่มีอ้างถึง |
| `s3-circular.pdf` | หนังสือเวียน | เลขอารบิก มีตราประทับ "ด่วนที่สุด" **และ** "ลับ" พร้อมกัน |
| `s4-external-scan.pdf` | หนังสือภายนอก | **ภาพสแกนจำลอง** (เอียง ขาวดำ เกรน เงา) ไม่มีข้อความให้ดึงตรงๆ ต้อง OCR |
| `s5-received-stamp.pdf` | หนังสือภายนอก | **ตราประทับรับ** (เลขรับ ๔๕๘, ๑๔ ก.ค. ๖๙) ที่ต้องไม่เอามาเป็นเลขที่/วันที่หนังสือ + อ้างถึง 2 ฉบับ |

### ชุด held-out (`h*`)

สร้าง**หลังจาก**ปรับตัวแยกฟิลด์แบบกฎกับ s1–s5 แล้ว เพื่อวัดว่ากฎใช้กับเอกสารอื่นได้จริงไหม (ฟอนต์/โครงหน้าต่างกัน)

| ไฟล์ | สิ่งที่ทดสอบ |
|---|---|
| `h1-wrapped-subject` | ฟอนต์ Sathu, เรื่องยาวสองบรรทัด, ไม่มีอ้างถึง/ตราประทับ |
| `h2-memo-inline` | ฟอนต์ Ayuthaya, "ที่ … วันที่ …" อยู่ช่วงเดียวกัน, ส่วนราชการยาวสองบรรทัด |
| `h3-words-not-stamps` | ฟอนต์ Sukhumvit Set, ในเนื้อหามีคำว่า "ด่วน"/"ลับ" แต่ไม่ใช่ตราประทับ |
| `h4-centered-header` | ชื่อหน่วยงานกึ่งกลางเหนือเลขที่หนังสือ |

**สถานะ:** ผลรันครั้งแรกของโหมดในเครื่องกับชุดนี้ถูกครบ 0/4 ฉบับ (รวม 74% เทียบกับ 4/4 ของชุดที่ใช้ปรับกฎ) หลังจากนั้นผมแก้กฎตามที่เห็น จึง**ไม่ใช่ held-out อีกต่อไป** ผลปัจจุบันใช้เป็นชุดทดสอบถอยหลัง (regression) เท่านั้น การวัดความแม่นยำจริงต้องใช้เอกสารชุดใหม่ที่ยังไม่เคยเห็น

`h1`–`h3` เป็นไฟล์ที่ฟอนต์ไม่เก็บวรรณยุกต์ไว้ในข้อความ (ใช้ทดสอบการตรวจจับ "ข้อความไม่ครบ") โหมดในเครื่องจะผิดในไฟล์เหล่านี้ แต่ต้องขึ้นคำเตือน

`expected.json` คือเฉลยของแต่ละฉบับ (ค่าหลัง normalize: เลขไทย→อารบิก, วันที่ `dd/mm/yyyy` พ.ศ.)

## สร้างใหม่

```sh
python3 build_samples.py   # ต้องมี Google Chrome (ใช้โหมด headless พิมพ์ HTML เป็น PDF)
```

## วัดความแม่นยำ

```sh
cd ..
node eval/run.mjs --self-test                      # ทดสอบตัวให้คะแนน (ไม่ใช้เครือข่าย)
PROVIDER=local node eval/run.mjs                   # โหมดในเครื่อง ไม่ใช้ AI/เครือข่าย (ต้อง cd eval && npm install ก่อน)
ANTHROPIC_API_KEY=sk-ant-... node eval/run.mjs     # รันจริง (ส่งเอกสารสมมติไปยัง API และมีค่าใช้จ่ายเล็กน้อย)
PROVIDER=openai OPENAI_API_KEY=... MODEL=<model-id> node eval/run.mjs
```

ผลบอกว่าฟิลด์ไหนผิดและควรได้อะไร พร้อมสรุปรายฟิลด์ บันทึกเป็น JSON ใน `eval/results/` เพื่อเทียบโมเดลต่างๆ ได้

**ข้อจำกัด:** ชุดนี้มีแค่ 5 ฉบับ และฟอนต์/ลายเซ็นเป็นของจำลอง ไม่มีลายมือจริง ตรารูปทรงอื่น หรือกระดาษยับ ผลที่ได้ใช้เปรียบเทียบโมเดลเบื้องต้นเท่านั้น ก่อนขายควรทดสอบกับเอกสารจริงของลูกค้า (ที่ได้รับอนุญาต)
