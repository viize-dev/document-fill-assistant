# Document Fill Assistant (Chrome Extension, MV3)

นำเอกสาร PDF เข้า → AI อ่านและแยกประเภท → ตรวจ/แก้ข้อมูล → กรอกฟอร์มในเว็บระบบปลายทาง → ออกใบปะหน้า

ตัว core ไม่ผูกกับระบบใด ทุกอย่างที่เฉพาะระบบอยู่ใน **profile** (ตอนนี้มี `saraban-demo` สำหรับเว็บทดสอบใน `../demo-extension`)

## ติดตั้ง (unpacked)

1. `chrome://extensions` → Developer mode → **Load unpacked** → เลือกโฟลเดอร์นี้
2. รันเว็บ demo: `cd ../demo-extension && npm run dev` แล้วเปิด http://localhost:4310
3. คลิกไอคอน extension เพื่อเปิด side panel → **ตั้งค่าการอ่านเอกสาร (OCR)** → เลือกผู้ให้บริการ (Claude / ChatGPT / Gemini) → ใส่ API key → "ทดสอบและโหลดรายการโมเดล" → เลือกโมเดล → บันทึก
4. เลือก PDF → ตรวจข้อมูล → **กรอกฟอร์ม** / **ใบปะหน้า**

ไม่มีขั้นตอน build

## โครงสร้าง

| ไฟล์ | หน้าที่ |
|---|---|
| `profiles/*.js` | **ข้อมูลเฉพาะระบบ**: URL, selector, ฟิลด์, ประเภทเอกสาร, รูปแบบวันที่, ใบปะหน้า |
| `profiles/index.js` | ทะเบียน profile + เลือกอัตโนมัติจาก URL |
| `lib/mapping.js` | ส่วนกลาง: แปลงวันที่ (พ.ศ./ค.ศ., เลขไทย, ชื่อเดือน), ค่า select, สร้างแถวให้ตรวจ |
| `lib/prompt.js` | สร้าง prompt จาก profile (ผลลัพธ์รูปแบบเดียวกันทุกค่าย) |
| `lib/providers/*.js` | adapter ต่อผู้ให้บริการ: `anthropic`, `openai`, `gemini` (และ `backend.js` สำหรับโหมดองค์กร ซึ่งปิดไว้) |
| `lib/cover.js`, `cover.*` | สร้างและแสดงใบปะหน้าจาก `profile.cover` |
| `lib/local/*` | โหมดในเครื่อง: ดึงข้อความ PDF (`pdftext.js`) + ตัวแยกฟิลด์แบบกฎ (`parsers/`) |
| `lib/deploy.js` | โหมดองค์กร: URL ของ backend จากนโยบาย/ค่าตอน build |
| `lib/docx.js` | ส่งออกใบปะหน้าเป็น Word (.docx) |
| `lib/sources/` | แหล่งไฟล์แบบ adapter: Gmail, Google Drive, โฟลเดอร์ในเครื่อง + `guard.js` (ตรวจ PDF/ขนาด), `history.js` (ป้าย "ทำแล้ว") · UI อยู่ที่ `sourcepanel.js` · แผน: `docs/PLAN-sources.md` |
| `content.js` | content script แบบกลาง: ตรวจหน้า, กรอก, อ่านค่า (รับ selector จาก side panel) |
| `sidepanel.*` | UI |

## ใบปะหน้า

เป็น**แบบกลาง** (เลย์เอาต์อยู่ใน `cover.js`/`cover.css` ใช้ร่วมกันทุกระบบ): หัวกระดาษ (ชื่อหน่วย / รับที่ / วันที่ / เรื่อง), กรอบ "เรียน" + ตัวเลือกติ๊ก (เพื่อโปรดพิจารณา / ดำเนินการ / ทราบ), วันที่กำหนด, หมายเหตุ และเส้นบรรทัดเขียนความเห็น
- **ทุกช่องแก้ไขได้บนหน้าใบปะหน้าก่อนพิมพ์** คลิกที่ข้อความหรือช่องสี่เหลี่ยม (ตอนพิมพ์เส้นประ/ช่วยดูจะไม่ติดไป)
- **เลขที่เอกสารในระบบ E** (มุมขวาบน) ดึงจากตราประทับในเอกสารที่อ่านได้ ไม่พบ = เว้นว่าง ฟิลด์นี้ไม่กรอกลงฟอร์ม (`fill: false` ใน profile)
- รับที่ = เลขทะเบียนรับที่อ่านจากหน้าปลายทาง, วันที่ = วันที่รับ (ถ้าไม่มีใช้วันนี้)
- ปรับได้ที่ `profile.cover` (`unit`, `options`, ป้ายต่างๆ, `lines`, `footerLabel`) และชื่อหน่วยตั้งได้ในหน้าตั้งค่า

## โหมดในเครื่อง (ไม่ใช้ AI)

เลือก "ในเครื่อง (ไม่ใช้ AI ไม่ต้องมี key)" ในหน้าตั้งค่า: อ่านข้อความที่อยู่ในไฟล์ PDF ด้วย pdf.js แล้วแยกฟิลด์ด้วยกฎ (`lib/local/`) ข้อมูลไม่ออกจากเครื่อง ไม่มีค่าใช้จ่าย

**ทำได้:** PDF ที่มีข้อความในไฟล์ (ส่งออกจากระบบสารบรรณ/Word) หนังสือภายนอก / บันทึกข้อความ / หนังสือเวียน ตราประทับชั้นความเร็ว/ลับ

**ทำไม่ได้ / ข้อจำกัด**
- **ภาพสแกนอ่านไม่ได้** (ยังไม่มี OCR): ระบบแจ้งว่าไม่มีข้อความในไฟล์ ให้ใช้โหมด AI
- **ข้อความในไฟล์อาจไม่ครบ:** PDF บางตัว (ขึ้นกับฟอนต์/โปรแกรมที่สร้าง) ไม่เก็บสระ/วรรณยุกต์ไว้ในข้อความ ระบบตรวจจับได้ (นับ `�` และสัดส่วนวรรณยุกต์) แล้วขึ้นคำเตือน ลดความมั่นใจทุกช่อง และแสดง `�` ตรงจุดที่ไม่รู้ **เติมกลับอัตโนมัติไม่ได้**
- กฎผูกกับโครงหนังสือราชการมาตรฐาน รูปแบบที่ต่างออกไปอาจพลาด (ชื่อหน่วยงานนอกแถวเลขที่ใช้ได้เฉพาะที่ขึ้นต้นด้วยคำที่รู้จัก)
- สรุปเรื่องไม่ได้ (รายละเอียด/ใบปะหน้าใช้ข้อความต้นฉบับท่อนแรกแทน)
- เกณฑ์ตรวจข้อความไม่ครบ (`MIN_TONE_RATIO`) วัดจากตัวอย่าง 8 ฉบับ ต้องทวนกับไฟล์จริง

**pdf.js** อยู่ที่ `lib/vendor/pdfjs` (v6.4.299, ~1.7 MB; เวอร์ชัน 5.6.83–6.2.107 มีช่องโหว่ระดับสูง ห้ามใช้) อัปเดตด้วย `scripts/vendor-pdfjs.sh` และตรวจ `npm audit` ใน `eval/` ทุกครั้ง

## ทดสอบและวัดความแม่นยำ

- `samples/` มี PDF หนังสือราชการ**สมมติ** 5 ฉบับ (รวมภาพสแกนเอียงและฉบับที่มีตราประทับรับหลอก) พร้อมเฉลย ใช้ลองกับเว็บ demo ได้ทันที
- `node eval/run.mjs` รันทุกฉบับผ่านโมเดลที่เลือกแล้วให้คะแนนรายฟิลด์ (ดู `samples/README.md`); `PROVIDER=local node eval/run.mjs` วัดโหมดในเครื่อง (ต้อง `cd eval && npm install` ก่อน)

## เพิ่มระบบปลายทางใหม่

1. คัดลอก `profiles/saraban.js` เป็นไฟล์ใหม่ แล้วแก้
   - `urlPatterns` / `detect`: หน้าไหนคือหน้าฟอร์ม
   - `fields`: ฟิลด์ทั้งหมด (`selector`, `kind`, `options`, `ask` = คำอธิบายให้ AI)
   - `docTypes`: ประเภทเอกสาร และฟิลด์ที่ต้องดึงของแต่ละประเภท
   - `dateFormat`: `{ era: 'BE' | 'CE', pattern: 'dd/mm/yyyy' }`
   - `cover`: รูปแบบใบปะหน้า
2. ลงทะเบียนใน `profiles/index.js`
3. ไม่ต้องแก้ core และ manifest: extension จะขอสิทธิ์ต่อเว็บเมื่อผู้ใช้กด "อนุญาตให้ใช้กับเว็บนี้"

Profile เป็น JSON-serializable ตั้งใจให้โหลดจาก backend ได้ในอนาคต (ขายหลายเจ้าโดยไม่ต้องออกเวอร์ชันใหม่)

## ผู้ให้บริการ AI และค่าใช้จ่าย

เวอร์ชันนี้ใช้ **API key อย่างเดียว** เหตุผล: Anthropic ห้ามแอปอื่นใช้ token ของแพ็กเกจ Claude, Google ไม่มีวิธีทางการให้ใช้ subscription Gemini ในแอปอื่น, และ "Sign in with ChatGPT" ยังเปิดเฉพาะ partner ที่ OpenAI คัดเลือก (ถ้าได้รับอนุมัติค่อยเพิ่ม)

โหมดองค์กร (login ผ่าน `../doc-fill-backend`) ยังมีโค้ดอยู่แต่ซ่อนไว้ใน UI (`fieldset.method[hidden]` ใน `sidepanel.html`)

| ผู้ให้บริการ | การเชื่อมต่อปัจจุบัน |
|---|---|
| Claude (Anthropic) | API key |
| ChatGPT (OpenAI) | API key |
| Gemini (Google) | API key |

- **ผู้จ่ายค่าใช้จ่ายคือเจ้าของ account ที่ออก key** ผู้ใช้ใส่ key ตัวเอง = ผู้ใช้จ่ายเอง; โหมดองค์กร = เจ้าของ backend (หน่วยงาน) จ่าย
- **ห้ามฝัง key ของผู้ขายไว้ใน extension**: จะรั่วและผู้ขายต้องรับค่าใช้จ่ายของทุกลูกค้า
- แพ็กเกจรายเดือนของแอปแชต (Claude Pro/Max, ChatGPT Plus/Pro, Gemini) **ไม่ใช่** API key และใช้กับ extension นี้ไม่ได้ (Anthropic ห้ามใช้ token แพ็กเกจกับแอปอื่น; "Sign in with ChatGPT" ยังต้องตรวจว่าขอเข้าร่วมได้หรือไม่)
- รายการโมเดลโหลดจากบัญชีของผู้ใช้จริง (model ID ของ OpenAI/Gemini เปลี่ยนบ่อย) ของ Claude มีรายการสำรองไว้ก่อน

## โหมดในเครื่อง: OCR ภาพสแกน

ไม่มี key AI หรือโควต้าหมด: โหมด "ในเครื่อง" อ่านภาพสแกนได้ด้วย OCR (tesseract.js + โมเดลภาษาไทย `tha` แบบ fast ~1 MB ไฟล์อยู่ใน `lib/vendor/ocr` อัปเดตด้วย `scripts/vendor-ocr.sh`) ทำงานในเครื่อง ไม่ส่งข้อมูลออกไปไหน

- อ่านเฉพาะ **หน้าแรก** ~3–8 วินาที/ฉบับ แล้วใช้ตัวแยกฟิลด์แบบกฎเดิม; ภาพจาง (หมึกสว่าง) ถูกปรับคอนทราสต์อัตโนมัติ
- ผลกับตัวอย่าง: ชื่อหน่วยงาน/ผู้รับ/เรื่อง/ประโยคปิดท้ายอ่านได้ดีเมื่อพิมพ์ชัด; **เลขที่หนังสือและวันที่มักผิด** (เลขไทย ตราประทับ ลายมือ) เลขที่ที่ไม่เข้ารูปแบบจะถูกเว้นว่าง ทุกช่องมีความมั่นใจไม่เกิน 50% และมีคำเตือน ผู้ใช้ต้องตรวจก่อนกรอก
- ใช้ pdf.js ถอดรหัส **JBIG2** (ภาพสแกนจากเครื่องสแกนเนอร์ส่วนใหญ่) ผ่านตัวถอดรหัส WebAssembly ใน `lib/vendor/pdfjs/wasm` — เดิมไม่ได้ vendor ไว้ ทำให้ PDF แบบนี้แสดงผลจาง/ว่าง (พบจากเอกสารจริง)
- ต้องใช้ Chrome 91+ (เอนจิน SIMD) และ manifest ตั้ง CSP `wasm-unsafe-eval` (ขนาดแพ็กเกจเพิ่ม ~9 MB)
- ทดสอบ: `node --test "test/*.test.mjs"` (มีเทสต์ OCR จริงกับ s4) และ `OCR=1 PROVIDER=local node eval/run.mjs`
- ⚠ ทดสอบในเบราว์เซอร์ด้วยหน้าจำลอง (ไม่ใช่ extension ที่ติดตั้งจริง) ต้องทดสอบหลังโหลด extension จริงอีกครั้ง

| profile | หน้า | สถานะการทดสอบ |

## โหมดองค์กร (admin ตั้งค่า API key ที่หลังบ้าน)

สำหรับลูกค้าองค์กร: ผู้ใช้ **ไม่เห็นและไม่ต้องกรอก API key** — login ด้วยบัญชีองค์กรแล้วใช้งาน admin คนเดียวตั้ง key/โมเดล/โควต้าที่หน้า `/admin` ของ backend (`../doc-fill-backend`)

- เปิดโหมดนี้โดยตั้ง URL ของ backend ได้ 2 ทาง: **นโยบายองค์กรของ Chrome** (`chrome.storage.managed`, schema ใน `managed_schema.json`, คีย์ `backendUrl`) หรือค่าตอน build ใน `lib/deploy.js` (`DEPLOY.backendUrl`) ไม่ตั้ง = โหมดเดิม (ผู้ใช้ใส่ key เอง/โหมดในเครื่อง)
- ในโหมดองค์กร: ส่วนตั้งค่าซ่อนผู้ให้บริการ/key/โมเดลทั้งหมด แถบด้านบนแสดงปุ่ม login ผู้ใช้ส่งเฉพาะ PDF + `profile_id` ให้ backend สร้าง prompt เอง (ผู้ใช้กำหนดข้อความที่ส่งให้ AI ไม่ได้) ไม่มีโหมดในเครื่องในโหมดนี้
- ซิงก์ profile ไป backend: `node scripts/export-profiles.mjs ../doc-fill-backend/profiles` (ทุกครั้งที่แก้ `profiles/*.js` หรือ `lib/prompt.js` — เทสต์ `test/org-mode.test.mjs` จะเตือนถ้าสองฝั่งไม่ตรงกัน)
- ⚠ ทดสอบแล้วด้วย backend จำลอง/เบราว์เซอร์จำลอง (login ผ่าน IdP จริงของ extension และ admin ยังไม่ได้ทดสอบ)

## สรุปเรื่องและใบปะหน้า

- โหมด AI สรุปเนื้อหา 2–3 ประโยคกระชับ (ไม่จำกัดจำนวนตัวอักษร กรอบในใบปะหน้าขยายตามเนื้อหา และไม่มีป้ายหัวข้อ) ในการเรียกเดียวกับการดึงฟิลด์ แสดงเป็นช่อง "สรุปเรื่อง (ใบปะหน้า)" ที่แก้ไขได้ แล้วลงช่องสรุปในกรอบใบปะหน้า
- โหมดในเครื่อง (ไม่ใช้ AI) **สรุปจริงไม่ได้** ได้เพียงข้อความต้นฉบับท่อนแรก (ตัดที่ขอบเขตคำ) ติดป้ายเตือนและความมั่นใจต่ำ
- วัดคุณภาพสรุป: `node eval/run.mjs` (ทุกโหมด) แสดงผลตรวจอัตโนมัติต่อฉบับ — ความยาว, ภาษาไทย, **ตัวเลข/วันที่ในสรุปต้องมีในเอกสารต้นฉบับ**, ใจความสำคัญ (`key_points` ใน `samples/expected.json`) ผ่านการตรวจไม่ได้แปลว่าสรุปดี ยังต้องให้เจ้าหน้าที่อ่านตัวอย่างจริง ตัวอย่างในโปรเจกต์เป็นเอกสารสมมติ
- ใบปะหน้ามีปุ่ม **ดาวน์โหลด Word (.docx)**: ใช้ค่าที่แก้บนหน้านั้น ช่องติ๊กเป็นช่องของ Word คลิกเปลี่ยนได้ในไฟล์ **ฝังฟอนต์ Sarabun** (Google Fonts, SIL OFL 1.1, ไฟล์ใน `lib/vendor/fonts`) ลงในไฟล์ ผู้รับเปิดบนเครื่องที่ไม่มีฟอนต์ก็เห็นตรงกัน (Word 2019+/Microsoft 365 ทั้ง Windows และ Mac, LibreOffice รองรับ; Google Docs/Pages/Quick Look ไม่อ่านฟอนต์ฝัง จะใช้ TH SarabunPSK ถ้ามี ไม่มีก็ฟอนต์สำรอง) ไฟล์ใหญ่ขึ้นราว 180 KB สร้างไฟล์ในเครื่อง ไม่ส่งข้อมูลออกไปไหน (`lib/docx.js`)
- ⚠ ไฟล์ .docx ตรวจโครงสร้างด้วย python-docx และดูตัวอย่างด้วย Quick Look ของ macOS แล้ว แต่ **ยังไม่ได้เปิดใน Microsoft Word / LibreOffice จริง** (เส้นเขียนความเห็นใช้แท็บมีเส้นนำ ซึ่ง Quick Look ไม่แสดง) ควรลองเปิดก่อนส่งลูกค้า

## เชื่อม Email / Drive (พักไว้ — ไม่อยู่ในรุ่นแรก)

แผนงานปัจจุบัน: `docs/PLAN-admin-backend-summary.md` (หลังบ้านให้ admin ตั้งค่า key + สรุปเอกสารลงใบปะหน้า) · แผนเดิมที่พักไว้: `docs/PLAN-sources.md`

ต้องตั้ง Google OAuth ก่อน (ใน `manifest.json` ยังเป็น placeholder):

1. Google Cloud Console → เปิด Gmail API และ Drive API
2. สร้าง OAuth client ชนิด **Chrome extension** ใส่ Extension ID
3. ใส่ client id ที่ `oauth2.client_id` แล้ว reload extension

ขอสิทธิ์อ่านอย่างเดียว (`gmail.readonly`, `drive.readonly`) ถ้าจะขาย ต้องผ่านการตรวจสอบแอปของ Google สำหรับ restricted scope (ดู `docs/PLAN-sources.md`)

**รุ่นแรกมีแค่อัปโหลดเอกสาร** (ตามหัวหน้าทีม) Gmail / Drive / Outlook / OneDrive / โฟลเดอร์ พักไว้และปิดอยู่ (เปิดได้ที่ `lib/sources/config.js` หลัง Google อนุมัติแอป และหลังลงทะเบียนแอป Microsoft แล้วใส่ `microsoftClientId`)

แท็บ "โฟลเดอร์" (ปิดอยู่ในรุ่นแรก) ไม่ต้อง login: เลือกโฟลเดอร์ในเครื่องครั้งเดียว (เบราว์เซอร์จะขอสิทธิ์อ่านใหม่เมื่อเปิดใหม่)

ทดสอบ adapter: `node --test "test/*.test.mjs"`

## ข้อจำกัด / ยังไม่ทำ

- Sign in with ChatGPT, โหมด local/on-prem
- โหมดองค์กรต้องกรอก URL ของ backend เอง (ยังไม่รองรับการตั้งค่าล่วงหน้าผ่านนโยบายองค์กร/managed storage)
- โหมดในเครื่องยังไม่มี OCR สำหรับภาพสแกน (วางแผน: tesseract.js)
- ยังไม่มีช่องแชต และใบปะหน้าเป็น template ตาม profile (ยังไม่ตรงแบบฟอร์มของหน่วยงานใด)
- รองรับเฉพาะช่อง text/textarea/select (checkbox, radio, date picker, select2 ต้องเพิ่มใน `content.js`)
- ชื่อผลิตภัณฑ์ "Document Fill Assistant" เป็นชื่อกลางชั่วคราว
- **ยังไม่ได้ทดสอบ side panel, การ login Google/Microsoft จริง, การเรียก AI ทั้ง 3 ค่าย และ Gmail/Drive ในเบราว์เซอร์จริง** ทดสอบแล้วเฉพาะ logic กลาง (unit test) และ content script กับหน้า demo
